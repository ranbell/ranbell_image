# LoRA の作り方 — ギャラリーから LoRA まで（今は Krea 2）

気に入った画像をギャラリーから**バケット**に溜めると、VLM が学習用のキャプションを書きます。
仕上がったらフォルダに書き出し、学習は ranbell の外の学習コンテナ（[external/musubi](../../external/musubi/README.ja.md)）で行います。

```
ギャラリー ──▶ バケット ──▶ キャプション ──▶ 書き出し ──▶ 学習 ──▶ ComfyUI で比較 ──▶ 公開
   (選ぶ)       (溜める)     (VLM が自動)    (フォルダ)   (musubi)
```

ranbell が受け持つのは「書き出し」までです。学習の起動や進捗は、学習コンテナ側のコマンドで扱います。

---

## 0. 準備（最初の1回だけ）

1. **書き出し先フォルダをマウントする。** ranbell の `docker-compose.override.yml` の backend に、
   ホストのフォルダを `/mnt/lora_export` として（書き込み可で）マウントし、backend を作り直します。
   ```yaml
         - /path/to/lora/datasets:/mnt/lora_export
   ```
2. **管理画面で確かめる。** 管理画面のモデル設定にある 📦 の2項目のうち、「書き出し先フォルダ」の下に
   「✓ 書き込めます」と出ていれば OK です。もう1つの「キャプション用モデル」は空なら VLM モデルを使います。
   選ぶなら**画像を読めるモデル**にしてください。
3. **学習コンテナを用意する。** [external/musubi の README](../../external/musubi/README.ja.md) の手順で
   コンテナを作り、Krea 2 の学習に使うモデル3点を置きます。

   ```
   docker-musubi/work/models/krea2/
     raw.safetensors               Krea 2 Raw（bf16、約26GB。Hugging Face で同意してから取得）
     qwen3vl_4b_bf16.safetensors   テキストエンコーダ（bf16、単一ファイル）
     qwen_image_vae.safetensors    VAE
   ```

   ComfyUI 用の fp8 版（`*_fp8_scaled`）は**使えません**。学習器は bf16 を読んで自分で量子化します。
   全体の配置図と取得元は [external/musubi の「ファイルの配置」](../../external/musubi/README.ja.md#ファイルの配置krea-2) にあります。

## 1. 画像を集める

ギャラリーで画像を選び、下のトレイの **「📦 LoRA バケット」** を押します。

- 新しいバケットを作るなら、左上で**対象モデル**を選び、名前を入れて「作成してN枚追加」。
  対象モデルは、どの画像モデル向けの LoRA かです（今は Krea 2 のみ）。モデルによってキャプションの書き方が変わります。
- 既存のバケットに足すなら、左の一覧で選んで「選択中のN枚を追加」。すでに入っている画像は自動で飛ばします。

入れた画像から順に、裏でキャプション作成が始まります（描画中は自動で一時停止し、カードが空くのを待ちます）。

**何枚、どんな画像を？**

| 作りたいもの | 枚数の目安 | 集め方 |
|---|---|---|
| 画風（塗り・線・色の雰囲気） | 30〜50枚 | **画風は揃え、中身はばらばらに**。人物・物・風景・構図に幅を持たせる |
| キャラクター | 20〜30枚 | **顔は同じ、それ以外はばらばらに**。表情・角度・服・背景を変える |

同じ構図や同じ小物ばかりだと、それも一緒に覚えてしまいます。
短い辺が 768px 以上あれば十分です。リサイズは学習時に自動で行います（拡大はしません）。

## 2. トリガーワードと学習対象を決める

バケット画面の上部で、2つを設定して **「保存して適用」** を押します。
（同じ並びにある「対象モデル」を後から変えると、全部の画像を描写し直します。手で直した行は残して印を付けます。）

### トリガーワード

LoRA を呼び出す合言葉です。全キャプションの先頭に自動で付きます。
**意味を持たない造語**にしてください（例：`zqx_style`、`rnbl_girl`）。普通の単語だとモデルが元々知っている意味と混ざります。

### 学習対象（キーワード）

ここに入れた言葉と、その言葉が表す描写は**キャプションから抜かれます**。

> **キャプションに書かれなかった共通点を、トリガーワードが覚えます。**
> だから「覚えさせたいもの」はキャプションから消し、それ以外（中身）はしっかり書いておきます。

| 作りたいもの | 学習対象に入れる例 | 入れないもの |
|---|---|---|
| 画風（flat など） | `flat colors, flat shading, cel shading, vector art, minimal shading, no gradients` | 人物・服・背景などの中身 |
| キャラクター | そのキャラの見た目（`white hair, blue eyes, hair ornament` など） | 服・ポーズ・背景（変えたいもの） |

- 「anime illustration」のような**画材の言葉を入れると、それも一緒に覚えます**。
  画風だけを覚えさせたいなら入れないでおきます。
- 色や塗りのキーワードを入れても、髪や服の色は消えません（「描き方」の言葉だけを抜きます）。
- キーワードは後から変えられます。画像は読み直さず、抜き取りだけがやり直されます。

---

## 3. キャプションを確かめる

全件が「済」になったら、何枚か **「全文」** を開いて、抜き取り後のキャプションと見比べます。

- **抜くべき言葉が残っていないか**（画風なら `minimalist`、`stylized` など）→ 学習対象に足して「保存して適用」
- **中身まで消えていないか** → その行を直接書き換える（欄の外をクリックで保存）

手で直した行は、その後の作り直しで上書きされません。
キーワードを変えたあとに手直しの行も作り直したいときは「手直し分も作り直す」を押します。
画風が揃っていない画像は「外す」で抜いておくと、仕上がりがぼやけません。

## 4. 書き出す

**「フォルダに書き出す」** を押すと、書き出し先に `<バケット名>/` ができます。

```
<書き出し先>/<バケット名>/
  <sha>.png   画像（PNG に変換し、メタデータはすべて削除）
  <sha>.txt   キャプション
  meta.json   対象モデル・トリガー・学習対象・各画像のサイズ
```

画像は JPEG や WebP でも PNG に変換し、プロンプト・ComfyUI のワークフロー・EXIF・カラープロファイルを
すべて落とします（向きと色は画素に反映するので、見た目は変わりません）。
原本の置き場所もどこにも書かれないので、データセットはそのまま人に渡せます。

学習コンテナは `meta.json` の対象モデルを見て、そのモデルの学習手順を選びます。

- 書き出しが終わると「書き出しが完了しました（N枚）」と知らせが出ます。
- 未処理やエラーの画像が残っていると書き出せません（ボタンにカーソルを載せると理由が出ます）。
- 書き出し直すとフォルダは丸ごと差し替わります。「zip で落とす」で同じ内容を zip でも取れます。

## 5. 学習する

**学習の前に、ranbell のコントロールルームで GEN レーンを一時停止**してください。
同じ GPU を使うので、学習中に描画が始まると両方落ちます。

```sh
cd /path/to/docker-musubi
docker compose exec musubi train <バケット名> --dry-run   # 確認（何も実行しない）
docker compose exec musubi train <バケット名> --epochs 30
```

- 学習の前に ComfyUI と Ollama のメモリを自動で空けます。
- epoch ごとに LoRA が保存されます。総 step 数は「画像の枚数 × epoch」です。
- 時間の目安（16GB カード）：1 step 約15秒。18枚 × 30 epoch で約2時間20分。
- 長いので `tmux` などの中で動かすのがおすすめです。Ctrl-C で止めても、そこまでの保存は残ります。

### 進み具合を見る

```sh
docker compose exec musubi status -w 60
```

進捗・残り時間・epoch ごとの loss・保存済みファイルが出ます。
**loss は異常（急な跳ね、NaN）に気づくためのもので、良し悪しは絵を見て決めます。**

## 6. 比較シートで比べる

学習が終わったら GEN レーンを再開し、`output/<バケット名>-<日時>/` の LoRA を
ComfyUI の loras フォルダに置きます。epoch 違いを比べるなら、**サブフォルダにまとめて**置くと楽です
（例：`loras/my_style/my_style-000010.safetensors`）。最初は間を空けて3〜4本（例：10・20・30 epoch）がおすすめです。

ranbell の **📊 LoRA 比較シート**で、同じシード・同じプロンプトのまま、LoRA ごとに strength を振って描き比べます。

- 開き方は3通り：
  - バケット画面の「📊 このバケットの LoRA を比べる」（LoRA の一覧をバケット名で絞り込み、バケットのトリガーを「新しく足す行のトリガー」に入れた状態で開く）
  - ギャラリーで絵を1枚選んで、トレイの「📊 LoRA 比較」（その絵のプロンプト・シード・モデルと縦横比を引き継ぐ。大きさはメガピクセルで指定、1 MP = 1024×1024）
  - 何も選ばずに開いて、一から設定する
- 作成フォームの内容は下書きとして残り、閉じて開き直しても戻ります。空からやり直すときは「リセット」
- **行 = LoRA、列 = strength**（既定 0 / 0.25 / 0.5 / 0.75 / 1 / 1.25）。**0 の列は LoRA なし**の素のモデルで、比べる基準です。
  トリガーが同じ行どうしは 0 の列を1枚だけ描いて共有します
- 各行のトリガーはプロンプトの先頭に付きます（プロンプト欄には書かない）
- 「トリガーなし列」を入れると、strength 1 でトリガーを外した列が足されます。効きすぎの確認用です
- グラフは ranbell が ComfyUI 標準ノードだけで組みます（保存済みワークフローは不要。LoRA は `LoraLoaderModelOnly`）。
  モデル（DiT・テキストエンコーダ・VAE）は ComfyUI のフォルダから選び、既定の描画設定は Turbo（8 steps / cfg 1）です
- 描画はジョブスケジューラ経由で、描けたマスから埋まります。止めても描けた分は残り、「続きを描く」で残りだけ描きます
- 「🎲 シードを変えて複製」で別シードのシートを作り、たまたまの当たり外れでないかを確かめます
- 「⬇ PNG で保存」で、見出し付きの1枚絵になります（メタデータなし。公開ページに貼れます）
- 左の一覧は検索でき、LoRA ごと・モデルごと・日付ごとにまとめて表示できます。名前は見出しをクリックすると変えられます
- **並べて比べる**：一覧でシートを2つ以上チェックして「⇅ 並べて比べる」。strength の列をそろえて縦に積み、
  各シートの見出しには**違う設定だけ**（モデル、シード、プロンプトなど）が出ます。公式 Turbo と派生モデル、シード違いの比較に。
  この表も「⬇ PNG で保存」できます
- **比較ボード**：マスの 📌（拡大表示では `P` キー）で最大4枚を選び、「比較ボードを開く」。大きく横に並び、
  ホイールでの拡大とドラッグでの移動が全部の絵で連動するので、手元や背景の細部を同じ場所で見比べられます

他の人が作った Krea2 LoRA も、loras フォルダにあれば同じシートに並べて比べられます。
学習に入れていない題材（車、料理、街並みなど）のプロンプトでもう1枚作ると、ちゃんと身に付いたかが分かります。

| 見え方 | 判断 |
|---|---|
| 早い epoch では弱く、後半で狙いどおりになる | 順調。いちばん自然な回を選ぶ |
| 早い epoch でもう十分 | 早めの回を選ぶ。次はもっと短くてよい |
| 最後まで弱い | 枚数か epoch を増やしてもう1本 |
| トリガーなしでも効く、学習画像の小物や構図が出てくる | 効きすぎ。前の epoch を使うか、強さを下げる |

ベースモデル（公式 Krea 2 Turbo か、派生モデルか）によって効き方が変わることがあります。

## 7. 公開する（任意）

```sh
docker compose exec musubi publish <バケット名> --epoch 20
```

学習日時やファイル名などを消した公開用のコピーが `output/<実行名>/publish/` にできます（重みはそのまま）。

Krea 2 の LoRA を配布するときは、[Krea 2 Community License](https://krea.ai/krea-2-licensing) の第3条に従います。

- モデル名の先頭を **「Krea 2」** にする（例：「Krea 2 Flat Style」）
- Krea 2 を元に学習した（改変した）ことを説明に書く
- ライセンスの表示を付ける（Civitai ではベースモデルに Krea 2 を選ぶと自動で表示されます）
- Krea の公式・公認と誤解させない

使う人のために、トリガーワード・おすすめの強さ・試したベースモデルを書き添えておくと親切です。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| キャプションが「描写待ち」のまま進まない | 描画中は自動で止まります。コントロールルームで ALIGNMENT（評価）レーンが止まっていないか確認。止まっていたら「続きを処理」 |
| キャプションがエラー「画像を読めない」 | 管理画面の 📦 キャプション用モデルで、画像を読めるモデルを選ぶ |
| 「書き出し先フォルダがありません」 | backend のマウントを確認（管理画面の表示が「✓ 書き込めます」になるまで） |
| 学習が VRAM 不足で落ちる | 自動で退避を増やしてやり直します。それでも落ちるなら `--preset 16gb-safe` |
| 学習が遅い | 画像の枚数と epoch を見直す。途中の epoch で十分なら Ctrl-C で止めてよい |
